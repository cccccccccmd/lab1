# S10 开源代码整理

> 目标：把研究代码整理成"陌生人 30 分钟内能复现主表"的公开仓库。开源质量影响论文可信度、引用量，也是部分会议的评审项。

## 1. 仓库结构（从研究仓库中整理出干净副本 `release/`）

```
README.md            # 见下方规格
LICENSE              # 默认 MIT（数据许可单独确认）
requirements.txt     # 精确固定版本（从实际环境导出后裁剪）
src/                 # 清理后的核心代码
configs/             # 论文中每个主要实验一份配置
scripts/
  prepare_data.sh    # 数据一键下载与预处理
  run_main.sh        # 一键复现主表
  run_ablation.sh    # 一键复现消融表
checkpoints/ 或下载脚本（模型太大则提供托管下载链接）
```

## 2. README 规格

依次包含：论文标题 + arXiv 链接 + 方法示意图；环境安装（含验证过的 CUDA/torch 版本组合）；数据准备；**"复现论文表 1"的最短命令序列**；预期结果表（复现数字与论文数字并列，标注允许波动范围）；预训练产物下载；引用 BibTeX；许可与致谢。

## 3. 清理纪律

- 删除：死代码、S6 迭代中被废弃的分支、内部路径、**一切密钥/token**（发布前跑一次密钥扫描，检查全部 git 历史；有泄漏历史则以干净历史重建仓库）。
- 保留：与论文最终版本对应的全部代码路径。对照论文逐表检查"每个数字都有对应的 config + 脚本"。
- 代码质量底线：关键函数 docstring、入口脚本 `--help` 可用、无绝对路径硬编码。

## 4. 验收：干净环境复现测试

在全新虚拟环境（或容器）中，仅按 README 从零走一遍：装环境 → 备数据 → 跑主实验（可用小规模配置验证流程 + 完整配置验证一个代表性数字）。复现值与论文差异超出标注波动范围则回去修，直到通过。

## 5. 出口

- 干净环境验收通过 → 整理发布材料（仓库、tag、版本说明），**呈报人类确认后再公开发布**（涉及匿名期的，先发匿名仓库）。
- 发布后：在 `RESEARCH_LOG.md` 写下整个项目的复盘：哪个阶段耗时超预期、哪些决策事后看是对/错的——这份复盘是下一个研究项目的起点。
