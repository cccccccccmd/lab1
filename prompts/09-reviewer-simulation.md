# S9 审稿人模拟与论文迭代

> 目标：在真实投稿前，用模拟评审把能被发现的问题全部发现并修复。迭代至多 3 轮或模拟评审达标。

## 1. 组建模拟审稿团（每轮执行）

用不同视角审 4 遍（可结合外部 LLM API 增加视角多样性，但你要独立完成每个角色，不能让单一模型的偏好主导）。每个角色输出标准审稿意见：Summary / Strengths / Weaknesses / Questions / 评分（1–10）+ 置信度。

| 角色 | 视角 | 重点火力 |
|---|---|---|
| R1 领域专家 | 最接近工作的作者 | 新颖性；与已有工作的区别是否实质；漏引 |
| R2 实验方法论者 | 严格的实证主义者 | 基线公平性；显著性；简单基线；val/test 纪律；消融完整性 |
| R3 领域外读者 | 相邻方向研究者 | 引言是否讲得懂；动机是否成立；写作与图表清晰度 |
| R4 冷酷的 AC | 拒稿理由搜寻者 | 用一句话概括杀死这篇论文的最强理由 |

模拟时的诚实要求：**按顶会真实标准打分，不因为是自己的工作而手软**。历史校准：ICLR 接收线约在均分 6（borderline accept）附近。

## 2. 意见分诊与修复

把 4 份意见合并去重，分为三类处理，全部记入 `REVIEWS/round-N.md`：

1. **可修复-写作类**（讲不清、漏引、图表问题）→ 直接改稿；
2. **可修复-实验类**（缺基线、缺消融、缺显著性）→ 回补实验（新开 exp-ID，走正常实验流程）；
3. **不可修复-根本性**（新颖性不足、问题不重要）→ 这是最重要的产出：如果 R4 的杀稿理由你无法用已有证据反驳，说明问题出在上游。呈报人类：是补做大实验、调整论文定位（换 claim/换赛道），还是接受降档投稿。

对每条意见写 rebuttal 式回应（改了什么/为什么不改），这份材料真实投稿收到意见时可直接复用。

## 3. 迭代与出口

- 每轮修复后重新模拟评审。**出口**：均分 ≥6 且无置信度高的致命弱点，或已完成 3 轮（3 轮后仍不达标 → 呈报人类决策）。
- 出口时产出《投稿建议书》写入 `RESEARCH_LOG.md`：推荐会议及截稿日期、预计评审风险 Top-3 及应对、是否先挂 arXiv 的建议。**最终投稿决策交人类。**

## 4. 提交前机械检查清单

匿名化（作者信息、致谢、自引口吻、代码链接）；页数与格式合规；参考文献逐条真实；图表在黑白打印下可读；补充材料完整；全文拼写与记号一致性检查。
