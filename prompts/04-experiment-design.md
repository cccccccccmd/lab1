# S4 实验设计

> 目标：产出 `EXPERIMENT_PLAN.md`——把提案的预期主表变成一份可执行、可复现、统计上站得住的实验计划。

## 1. 评测协议（先定协议，再写代码）

- **数据集与划分**：明确 train/val/test 来源与规模。没有官方划分的自己切并固定随机种子；**test 一旦切出，锁死**（写入只读目录），所有开发决策只看 val。
- **指标**：主指标 + 辅助指标，写明确切计算方式（宏平均还是微平均、截断规则、大小写归一等——细节不一致是复现失败的头号原因）。
- **显著性**：主要对比至少 3 个随机种子，报均值±标准差；样本级指标做配对显著性检验（bootstrap 或配对 t 检验），在计划中写明用哪种。
- **先测噪声底**：正式对比前，用同一配置不同种子跑 3 次基线，量出指标的天然波动幅度（std）。这个数字决定两件事：多大的提升才值得当真、需要几个种子才能区分你预期的效应量。预期提升 < 噪声底的实验设计直接推翻重来（要么放大效应，要么加大样本）。
- **数据污染检查**：所用 benchmark 是否可能在被测模型的预训练数据里？做基本核查（数据发布时间 vs 模型训练截止时间；抽样让模型补全测试题看是否背题），结果写入计划。污染的 benchmark 出好数字是无意义的。
- **阴性对照组**：设计 1–2 个"理应不 work"的对照——随机替换方法核心输入的版本、打乱标签训练的版本。如果阴性对照的指标也涨了，说明评测管线有泄漏或者提升来自无关因素。这是抓"虚假提升"最便宜的手段。
- **LLM 评测的特殊纪律**（如适用）：判分 prompt 固定版本并存档；judge 模型固定（版本号写死）；judge 与被评方法不得是同系列模型；抽 50 条人工抽查 judge 与人判的一致率并报告。

## 2. 基线选取

- 三类缺一不可：**经典强基线**（领域公认）、**最新 SOTA**（近一年顶会）、**简单基线**（越简单越好，用来证明问题不是平凡的）。
- 每个基线注明：官方代码链接 / 复现方式、原论文报告数字、我们的目标复现数字（允许 ±1 点）。
- 公平性检查表：所有方法用同样的数据预处理、同样的评测脚本、可比的调参预算（把每个方法允许的搜索空间写进计划）。

## 3. 实验矩阵

把要跑的实验列成带编号的表，按依赖顺序排列，每行含：

```
exp-ID | 目的（验证哪个假设） | 配置要点 | 预计耗时 | 依赖 | 判据（什么结果算通过）
```

必含的实验组：
1. **E0 冒烟测试**：1% 数据全流程跑通；
2. **E1 基线复现组**：逐个对齐公开数字；
3. **E2 主方法 v1**：与基线首次正面对比；
4. **E3 预留：改进循环**（S6 阶段动态追加，编号连续）；
5. **E4 消融组**：核心组件逐一移除/替换（S7 详化，此处先占位列出计划消融的组件）；
6. **E5 稳健性组**：跨数据集泛化、规模敏感性、超参敏感性。

## 4. 硬件适配核查

- 每个实验标注：显存峰值预估、本地可跑/需 API/需云 GPU。
- 6GB 显存下的标准配置参考：QLoRA 4bit + gradient checkpointing + batch=1 + 梯度累积；≤1.5B 模型可 bf16 推理，3B 需 4bit 量化推理。
- 单实验 >2 小时的：写入后台运行方案（nohup + 日志文件 + 检查点续跑）。

## 5. 目录与命名规范

```
EXPERIMENTS/
  exp-001-smoke/          # 每个实验一个目录
    config.yaml           # 完整配置（含种子）
    run.sh                # 一键复跑
    logs/                 # 原始输出，永不手改
    report.md             # 假设→预期→实际→结论（模板见 templates/）
  RESULTS.md              # 汇总表：所有实验的关键数字，随时可生成主表
```

## 6. 出口

`EXPERIMENT_PLAN.md` 完成，实验矩阵可以从上到下顺序执行 → 更新 `RESEARCH_LOG.md`，进入 S5。
