# S6 指标改进循环（核心阶段）

> 目标：通过**假设驱动的迭代**把方法从 v1 打磨到显著超越最强基线——或者诚实地判定此路不通。
> 本阶段是拉开论文档次的地方：顶会论文和平庸论文的差距，大多产生于这里的迭代质量。

## 1. 循环结构（每一轮严格走完五步）

```
┌─> ① 误差分析 → ② 提出假设 → ③ 最小改动实验 → ④ 对照判定 → ⑤ 记录与决策 ─┐
└──────────────────────────── 回到 ① ──────────────────────────────────────┘
```

### ① 误差分析（每轮的起点，不许跳过）
- 从 val 集抽取当前方法的失败案例 **≥30 个**（若失败少，抽相对基线变差的案例），逐个看原始输入输出。
- 归纳失败类型，做成分布表：`失败类型 | 占比 | 典型例子 | 疑似原因`。
- 同时看"意外成功"的案例——方法在你没预期的地方变好，往往暗示真实的作用机制与你的假设不同（这本身可能是论文的分析亮点）。

### ② 提出假设
- 针对**占比最大且疑似原因最明确**的失败类型，提出一条机制假设："失败是因为 M；若修复 M，该类型错误应下降 X%，总指标应升 Y。"
- 禁止无假设的改动。"试试调大学习率"不是假设；"当前 lr 下 loss 曲线后期震荡说明步长过大，减半应使收敛更低"才是。

### ③ 最小改动实验
- 每轮**只改一个变量**，新开一个 exp-ID，config 与上一版的 diff 必须一行能说清。
- 先在子集（10–20% 数据）快速验证方向，方向对了再跑全量——6GB 显存下这能省一半时间。

### ④ 对照判定
- 与上一最优版本在**相同种子集**上对比；提升小于噪声水平（±std）的不算提升。
- 检查提升是否恰好来自 ② 预测的失败类型（分类型指标）。**总分升了但预测类型没变化 = 你的机制解释是错的**，即使收益保留，也要修正认知再继续。

### ⑤ 记录与决策
- report.md 写完整：假设、预期、实际、结论（支持/否定/意外）。
- **感悟台账**：每轮结束提炼一条**可迁移的一般性认识**写入 `RESEARCH_LOG.md`「关键结论」——不是"exp-012 涨了 0.8 个点"，而是"该任务的主要瓶颈是 X 而非公认的 Y，证据是……"。这些条目会累积成论文分析章节的骨架，也是这项研究真正的智识产出。提炼不出一般性认识的一轮，说明实验设计缺乏区分度，下一轮要改进的首先是实验而不是方法。
- 更新 `RESULTS.md` 汇总表和 `RESEARCH_LOG.md`。
- git 提交本轮改动。

### 每 5 轮：元回顾（跳出循环看循环）
连续迭代容易陷入局部视野。每完成 5 轮，强制做一次元回顾并记入日志：
1. 重读 `PROPOSAL.md` 的预写摘要——我们还在做那篇论文吗？跑偏是发现了更好的方向（正式修订提案），还是无意识漂移（拉回）？
2. 失败类型分类学过时了吗？（连续修复后，当初的分类可能已不反映现状，用最新失败案例重建一次分布表）
3. 这 5 轮的感悟台账连起来讲了一个什么故事？它暗示下一个大动作是什么——继续微调，还是方法该有一次结构性改版？

### 平台期破局清单（收敛出口触发前先试这些）
连续几轮收益递减时，按序尝试（每项仍走五步循环）：
① 换归因维度重做误差分析（之前按错误类型分，改按输入长度/难度/领域分，常暴露新结构）；② 做规模探针（数据减半/模型换档，看瓶颈是容量还是方法）；③ 回到数据（人工精读 20 个原始样本，检查任务定义本身是否有含糊之处）；④ 重读 S1 的矛盾清单（现在的你可能能看懂当时看不懂的线索）。

## 2. 改进方向的优先级

按性价比排序，逐层用尽再下移：

1. **修 bug 与数据质量**：占实际增益的比例远超预期。每轮先自查：标签噪声？预处理丢信息？评测对齐？截断问题？
2. **修复误差分析暴露的机制缺陷**（本阶段主体）。
3. **方法组件的替换/增强**：每次新增组件必须记录"为什么加、解决哪类失败"——这些记录就是 S7 消融表的行。
4. **超参搜索**：放最后，且给基线同等搜索预算。用小规模网格/贝叶斯搜索，搜索空间写入 config。

## 3. 纪律与反模式

- **禁止看 test**：整个 S6 只许用 val。test 只在宣布"迭代结束"后评估一次。
- **防 val 过拟合**：val 上决策次数记在 `RESEARCH_LOG.md`；决策超过 ~20 次时，切出第二个 held-out 子集做最终裁决。
- **反模式清单**（发现自己在做就立即停）：
  - 连续 3 轮无假设的乱试超参；
  - 为保住某个好数字而不敢重跑多种子；
  - 把偶然一次的好结果当作稳定提升（必须 3 种子确认）；
  - 改动越堆越多但没有任何一轮做过归因。

## 4. 停止条件（满足其一即出循环）

- **成功出口**：3 种子均值显著超最强基线（配对检验 p<0.05），且提升幅度达到 `PROPOSAL.md` 的最小发表条件 → 锁定最终配置，跑 test（一次），进入 S7。
- **收敛出口**：连续 5 轮假设驱动的改进收益均 < 噪声 → 判定当前思路收益见顶。评估现有优势是否已够发表条件；够则进 S7，不够走失败出口。
- **失败出口**：误差分析显示核心假设被系统性否定（方法的前提不成立）→ 这是有价值的科学结论。在 `RESEARCH_LOG.md` 写清死因与证据，评估两条路：(a) 转型为分析类论文（"为什么直觉上应该有效的 X 其实无效"，顶会接受这类论文，但需要把机制挖得极深）；(b) 回 S2 换想法。呈报人类决策。

## 5. 时间与并行

- 长训练挂后台，等待期间：写论文的 Related Work / Method 章节草稿、准备下一轮实验、整理代码。
- 每个工作日等效结束时，`RESEARCH_LOG.md` 的 `next_actions` 必须具体到"新会话零记忆可执行"。
