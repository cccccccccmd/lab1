# S2 创新点探索与筛选（核心阶段）

> 目标：产出 **1 个**通过三重闸门、值得押注数周实验的创新点。
> 心法：创新点不是靠灵感"想"出来的，是靠**结构化生成 + 无情筛选**得到的。宁缺毋滥——一个平庸的想法会浪费后面所有阶段的努力。

## 0. 什么样的创新点配得上 CCF-A

先校准标准。顶会接收的论文，其创新点几乎都属于以下类型之一（按常见度排序）：

1. **发现并解决一个真实存在但被忽视的问题**（最强：问题本身就是贡献的一半）；
2. **对"为什么 X 有效/失效"给出新的机制解释，并由解释导出更好的方法**；
3. **打破一个领域公认假设**，证明去掉/替换它更好；
4. **统一框架**：证明看似不同的方法 A、B、C 是同一框架的特例，并由框架导出新的更优点；
5. **换度量/换视角**：证明领域一直在优化错误的目标，提出正确的目标并给出优化方法；
6. **强实证研究/新基准**：系统性揭示现有方法的共同盲区（NeurIPS D&B、分析类论文）。

**不配的**：A 方法 + B 场景的平移缝合（除非平移中出现了需要新技术解决的独特挑战）；只涨点不解释为什么的 trick 堆叠；无法在你的资源下验证的宏大构想。

## 1. 批量生成：每个 gap 至少 3 个候选，总数 ≥10

对 `SURVEY.md` 中的每个 gap，系统性套用以下 8 个生成算子（不是每个都适用，但每个都要认真尝试）：

| 算子 | 操作 | 触发问题 |
|---|---|---|
| 假设反转 | 取领域假设清单中的一条，问"如果它是错的呢" | 这个假设最可能在什么场景破？破了之后现有方法差多少？ |
| 失效挖掘 | 拿 SOTA 方法找它系统性失败的输入子集 | 失败案例有没有共同结构？这个结构暗示什么缺陷？ |
| 机制追问 | 对一个公认有效的 trick 问"它到底为什么有效" | 已有解释是否经得起对照实验？更准确的解释能否导出更好的方法？ |
| 矛盾仲裁 | 取矛盾清单一条，设计实验找出隐藏变量 | 什么条件下 A 对、什么条件下 B 对？条件本身是不是新发现？ |
| 极限降解 | 把某关键资源（数据/参数/监督信号）砍到 1/10 | 哪个方法崩得最快？为什么？能否设计在极限下仍稳健的方法？ |
| 跨域嫁接 | 从相邻领域借一个**原理**（不是方法照搬） | 该原理解决的抽象问题在本领域是否同构？平移时出现什么新挑战？ |
| 组合失配 | 找两个"理应兼容却没人同时用"的技术 | 是没人想到，还是组合会互相破坏？破坏的原因能否成为研究对象？ |
| 度量质疑 | 审视领域主流指标 | 指标高但实际差的案例存在吗？能构造吗？正确的度量是什么？ |
| 第一性原理重构 | 假装该领域的现有方法全不存在，从问题本身出发从零设计解法 | 你的白板设计与现状的差异在哪？差异处是历史包袱还是必然选择？ |
| 资源极端化 | 想象算力/数据 ×100 或 ÷100 时的最优解 | 极端情形下的最优方法与今天的差异，暗示了当前方法的什么妥协？该妥协可以被更聪明的设计替代吗？ |
| 反常现象驱动 | 收集调研和实验中"不符合领域共识预期"的小现象 | 这个反常能稳定复现吗？现有理论解释得了吗？解释不了的反常是新机制的入口（科学史上最高产的算子） |

**杂交轮**：单算子生成结束后，把候选清单里任意两个想法两两配对审视一遍，问"A 的机制能否解决 B 的弱点"——组合出的复合想法若比双亲都强，作为新候选入库。真正的好想法常在这一轮出现，因为单点想法容易被人做过，而有机组合的空间大得多。

每个候选立即按 `templates/idea-card.template.md` 建卡写入 `IDEAS.md`，核心是把想法压缩成一条**可否证的假设**：
> "我们假设 **[具体机制/现象]**，如果为真，则 **[某可测量指标]** 应当 **[方向与幅度]**；若观察到 **[相反证据]**，该假设即被否定。"

写不成这个格式的想法直接淘汰——不可否证的想法做不成论文。

## 2. 三重闸门（顺序执行，任一不过即淘汰，淘汰理由写入卡片）

### 闸门 A：新颖性检索（每个候选 15–30 分钟）

- 用 3 组不同措辞检索 arXiv / Semantic Scholar / Google Scholar（包括该想法的英文术语变体）；检索 OpenReview 看是否有被拒的同类想法（如有，读审稿意见了解它死在哪）。
- **引文图谱行走**：找到最接近的 1–2 篇论文后，沿它们的引用（向后）和被引（向前）各走一层——同一个想法的变体最常藏在最接近论文的邻居里，纯关键词检索会漏掉措辞不同的近亲。
- 结论三选一：**已存在**（淘汰，记录最接近论文）；**部分重叠**（记录差异点，差异必须是实质的，"换个数据集"不算）；**未发现**（通过）。
- 警惕：检索不到 ≠ 新颖，可能是措辞问题。对"未发现"的候选，额外从它的预期结论反向检索一次。

### 闸门 B：价值与可行性评分

对通过闸门 A 的候选，按 5 维打分（1–5 分），写入卡片：

1. **重要性**：解决的问题有多少人关心？能否用一句话向非本方向的研究者讲清楚为什么重要？
2. **新颖度**：与最接近工作的实质差异大小。
3. **预期效果**：如果假设为真，指标/认知上的收益幅度。
4. **资源可行性**：6GB + API 条件下，完整实验能否在 2–4 周内完成？（≤2 分的直接淘汰）
5. **故事清晰度**：能否用"问题→洞察→方法→验证"四句话讲圆？

**冷却重审**：评分完成后不要立即推进。至少隔一个工作会话（写入 next_actions，下次会话第一件事执行），换"最强反对者"人格重审前 5 名：为每个想法写一段 100 字的、最有杀伤力的反对陈词，然后再看评分是否需要修正。热情是评分的系统性噪声，冷却是唯一的去噪手段。

总分排序，取前 3 名进入闸门 C。**在此暂停，把前 3 名的完整卡片、各自的反对陈词和你的推荐呈给人类确认。**

### 闸门 C：廉价否证实验（kill experiment，每个 ≤2 小时机器时间）

为每个入围候选设计一个**最小否证实验**——注意方向：不是"验证它可行"，而是**尽全力杀死它**。原则：

- 测试假设链条中**最脆弱的一环**，而不是最容易做的一环；
- 用最小数据/最小模型跑，只要能让假设的预测方向显现即可；
- 事先写下判据："出现什么结果就放弃"。事后严格执行，不许为存活而移动球门。

典型的 kill experiment：假设"现有方法在 X 场景失效"→ 先构造 50 个 X 场景样本，实测现有方法是不是真的失效（很多想法死在这一步：所谓的问题根本不存在）。

## 3. 出口

- 存活下来的候选（通常 1 个，偶尔 0 个）：卡片补全 kill experiment 结果，标记为 `SELECTED`，进入 S3。
- 全军覆没：这是常态而非失败。带着淘汰理由回到 S1 补充调研或换 gap，重新生成一批。**绝不为了推进进度而放行一个自己都不信的想法。**
- 更新 `RESEARCH_LOG.md`。

## 4. 本阶段心法备忘

- 数量产生质量：前 5 个想法几乎总是别人也想得到的，真正的机会常出现在第 7–15 个。
- 好想法的手感：听到的人会说"咦，确实，为什么没人做过这个？"——既意外又显然。
- 对自己最初的偏爱保持怀疑：你为一个想法投入的沉没成本越多，越要主动找证据反对它。
