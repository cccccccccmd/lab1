# S7 消融实验与深入分析

> 目标：回答审稿人必问的两个问题——"增益到底来自哪？"和"什么时候会失效？"。本阶段产出的分析章节，常常比主表更能决定论文的档次。

## 1. 消融矩阵（E4）

- 对方法的每个组件：**移除**（还原为基线做法）与**替换**（换成合理的替代实现）两种消融，各跑 3 种子。
- 组件间有交互嫌疑的，补两两组合消融。
- 产出标准消融表：`配置 | 主指标 | Δ vs 完整方法`。理想形态：每个组件都有正贡献，核心组件贡献最大。
- **如实处理尴尬结果**：某组件消融后指标不降反升 → 从最终方法中移除它并更新主实验；这不是丑闻，提前发现胜过被审稿人发现。

## 2. 稳健性与敏感性（E5）

1. **跨数据集 / 跨分布**：至少 1 个与开发集分布明显不同的测试场景。
2. **规模趋势**：模型规模或数据量取 3 个点（如 0.5B/1.5B/3B，或 10%/50%/100% 数据），画趋势线。审稿人关心"规模上去后你的方法还有用吗"——趋势外推是 6GB 显存下你能给出的最好回答。
3. **超参敏感性**：核心超参在合理区间内扫 3–5 个值，证明结论不依赖精调。
4. **失效边界**：主动构造并报告方法失效的场景。诚实报告失效边界是顶会论文的加分项，且能提前拆掉审稿人的炸弹。
5. **成本-性能前沿**：报告方法相对基线的额外开销（推理 token 数/延迟/训练时长），画"指标 vs 成本"图。凡是用了更多计算的方法（test-time 方法尤其），审稿人必问"给基线同样的计算量它会不会一样好"——必须包含"计算量对齐的基线"这一行，否则对比不成立。
6. **压力测试**：对输入做保语义扰动（改写、换序、加干扰信息），比较方法与基线的性能衰减率。稳健性差距本身常是可写进论文的发现。

## 3. 机制验证分析（拉开档次的部分）

主表证明"有效"，本节证明"如你所解释的那样有效"。从以下选 2–3 个适用的：

- **分类型指标**：按 S6 的失败类型分解指标，展示增益集中在假设预测的类型上；
- **中间量观测**：直接测量假设涉及的中间变量（注意力分布、检索命中率、中间步骤正确率等），验证机制链条；
- **案例研究**：3–5 个精选案例，逐步展示方法如何改变了行为（论文正文用 1–2 个，其余进附录）；
- **反事实检验**：构造"假设机制被人为破坏"的对照（如打乱检索文档、扰动关键输入），验证性能按预期崩掉——机制真实性的最强证据。

## 4. 图表制作

- 每张图先写一句话结论（figure takeaway），一张图只讲一件事；
- 生成脚本入库（`PAPER/figures/scripts/`），数据变了能一键重出图；
- 折线图带误差带（3 种子），柱状图带误差线；矢量格式（pdf）输出。

## 5. 出口

消融表完整、稳健性覆盖、≥2 个机制验证分析完成，所有数字入 `RESULTS.md` → 更新 `RESEARCH_LOG.md`，进入 S8。
