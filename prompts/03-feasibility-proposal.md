# S3 可行性论证与研究提案

> 目标：把选定的创新点变成一份完整的 `PROPOSAL.md`——它相当于论文的"骨架预演"，写完它你就知道这篇论文最终长什么样、可能死在哪。

## 1. PROPOSAL.md 结构（逐节完成）

### 1.1 问题陈述
- 一段话：现有方法在什么条件下、以什么方式失败/不足；这个失败为什么重要。
- 附 kill experiment 的实证证据（S2 已有）——提案里的问题必须是**被实测证实存在**的问题。

### 1.2 核心假设与方法草图
- 重申可否证假设（S2 卡片格式）。
- 方法草图：伪代码或流程图级别即可，但必须明确"与最接近的已有方法，算法上到底哪一步不一样"。
- **预写贡献列表**：以论文口吻写 3 条 "Our contributions are..."。写不出 3 条实质贡献，说明想法太薄，回 S2。
- **预写摘要**：现在就用论文八股（背景/问题/方法/结果/意义）写一版摘要，结果数字用占位符。这份摘要是全项目的北极星——之后每个阶段都对照它检查"我还在做这篇论文吗"，跑偏时要么纠偏要么正式修订摘要。

### 1.2b 机制论证（为什么应当有效）
在跑任何完整实验之前，把"方法 → 预期收益"的因果链条一环一环写出来，并做两件廉价的事：
- **量级估算**（back-of-envelope）：预期提升的来源在数据中占多大比例？就算该来源被完美解决，指标上限提升是多少？——很多想法在这一步就会暴露"天花板只有 0.5 个点"的致命问题。
- **玩具模型**：能否构造一个 100 行代码以内的合成任务，让方法的核心机制在其中被干净地展示？玩具实验成本极低，且日后常直接成为论文的 motivating example 或分析章节。

### 1.3 预期主表（关键练习）
- **在做任何实验之前，把论文的主结果表画出来**：行 = 方法（含所有基线），列 = 数据集×指标，格子里填预期数字区间。
- 这个练习强制回答：和谁比？在哪些数据集上比？赢多少才算赢？哪个格子是最可能输的？
- 同时写下"最小发表条件"：主表至少要达到什么水平，这篇论文才成立（例如：在 3 个数据集中至少 2 个显著超最强基线，且消融证明增益来自核心组件）。

### 1.4 实验资源预算
- 逐项列出：数据集（大小、下载来源、许可）、基线（代码来源、复现难度）、模型（本地跑什么、API 调什么）、单轮实验耗时、API 成本估算、总日历时间估算。
- 对照 `CLAUDE.md` 硬件约束逐项核查；任何一项超出本地能力的，给出降级方案（更小模型/子采样数据）或云 GPU 预算。

### 1.5 风险清单与预案
- 列出 Top-3 "这篇论文会死的方式"，各配一个预案。常见死法：
  1. 效果提升不显著 → 预案：分析为什么、转为分析类论文的可能性；
  2. 某强基线复现后发现问题已被隐式解决 → 预案：更换对比维度或问题设置；
  3. 方法只在小规模成立 → 预案：给出规模趋势外推证据，或诚实限定 scope。

### 1.6 里程碑
- 按周划分：W1 基线复现，W2 方法 v1 + 首次对比，W3–W4 迭代改进，W5 消融补全，W6 写作……（按实际调整）。

## 2. 自我审查（提案红队）

写完后，切换到"苛刻审稿人"视角，对提案自问并书面回答：

1. 这个问题是真问题还是我构造出来的稻草人？最强的反驳是什么？
2. 如果我是最接近工作的作者，我会说这个提案和我的差别在哪？够大吗？
3. 预期主表里赢面最小的格子输了怎么办？论文还成立吗？
4. 有没有一个更简单的方法（简单基线）可能达到同样效果？——**必须把这个简单基线加进主表**，顶会审稿人最爱用"一个简单基线就能做到"杀论文。
5. **Pre-mortem（事前验尸）**：假设一年后这篇论文被拒了，写出那封最可能收到的 meta-review（3–5 句）。然后检查：提案里有没有针对这封"未来拒稿信"的防御动作？没有就补进实验计划或风险预案。

## 3. 出口

- `PROPOSAL.md` 完成且自我审查通过 → 更新 `RESEARCH_LOG.md`，进入 S4。
- 审查中发现致命伤 → 回 S2，理由记录在案。
