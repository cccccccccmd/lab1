# 领域包：智能体记忆（Agent Memory）

## 0. 适配度与推荐切入角度（★★★★★）

纯 API + 本地轻量组件（嵌入模型、检索索引）即可开展，6GB 显存无压力，且该领域**评测基础设施仍不成熟**——这对资源有限的研究者是好消息：做出可信的评测/分析工作不需要大算力。
推荐切入角度：**记忆的评测科学**（现有基准能否区分"记忆能力"与"长上下文能力"？）、**遗忘与更新机制**（几乎所有工作只研究"存与取"，"改与忘"是显著空白）、**记忆错误的传播分析**（错误记忆如何在长程交互中滚雪球）。

## 1. 领域地图

- 主线演化：外挂向量库 RAG → 分层记忆管理（MemGPT 的 OS 式分页）→ 生成式智能体的反思与总结（Generative Agents）→ 结构化/图谱化记忆（HippoRAG 类）→ 当前焦点：**长程一致性、记忆更新与冲突消解、个性化**。
- 关键子问题：写入什么（原文/摘要/结构化三元组）；何时写入（每轮/事件触发/反思触发）；如何检索（相似度/时间/图遍历混合）；如何更新与遗忘（新旧信息冲突时信谁）；记忆与上下文窗口的分工；隐私与记忆安全。
- 与长上下文的张力是领域的核心矛盾：上下文窗口越来越长，外置记忆的存在理由必须被更精确地论证（成本、结构化、跨会话持久性）。

## 2. S1 定制

- 检索词族：`agent memory`、`long-term memory LLM`、`memory-augmented agent`、`episodic memory LLM`、`personalization dialogue memory`。
- 必读类型：MemGPT、Generative Agents、HippoRAG 原文；长程对话记忆基准（LoCoMo、LongMemEval 类）的论文——**重点读它们的错误分析章节**；认知科学中人类记忆模型的经典综述（编码-存储-提取-遗忘框架，是最好的跨域嫁接源）。
- GitHub Issues 富矿：MemGPT/开源记忆框架的 issue 区充满真实失败模式（重复记忆、过时信息、检索串台）。

## 3. 评测协议与基线

- 常用基准：LoCoMo、LongMemEval（长程对话问答）；跨会话个性化任务；自建长程交互模拟（可控性最好，也是本领域论文的常见做法——但要防"为自己方法量身定做"的偏置，见陷阱 2）。
- 必备基线：**全历史塞长上下文**（最重要的基线——你的记忆系统必须赢它或在成本上碾压它）、朴素 RAG（固定分块+向量检索）、滑动窗口+定期摘要。
- 指标：记忆命中类指标（时序推理、跨会话一致性、更新后正确性）+ **token 成本**；分开报告"检索失败"与"检索对了但没用上"两类错误。

## 4. 领域特有陷阱

1. 与长上下文基线不比或比得不公平（给记忆系统精调、给长上下文裸奔）——头号审稿雷区。
2. 自建评测数据自证有效：合成数据的生成规则若与方法机制耦合，结果无意义。自建基准必须有人工质检子集 + 在至少一个公开基准上验证。
3. 评测集"提问方式"泄漏检索线索（问题措辞与记忆原文高度重合，把任务退化为字符串匹配）——做改写扰动版对照。
4. 只测"记住"不测"该忘的忘了"：过时信息未更新导致的错误往往比遗忘更严重，需专门评测维度。

## 5. 创新点富矿（算子实例化）

- 假设反转："记得越多越好"——冗余记忆是否反而干扰检索与推理？"记忆应该忠实原文"——适度抽象/有损压缩是否更利于泛化？
- 失效挖掘：长程交互中收集记忆错误案例，建立错误分类学（过时、串台、粒度失配、时序混乱）——本身可成 benchmark 论文。
- 机制追问：反思式摘要（Generative Agents 式）到底贡献了什么？消融"反思"后哪类任务掉分？
- 空白矩阵：记忆的"写入/检索"研究密集，"更新/删除/冲突消解"稀疏；单 agent 记忆密集，多 agent 共享记忆稀疏。
- 跨域嫁接：认知心理学的间隔重复、提取练习效应、干扰理论；数据库的事务与版本控制（记忆一致性问题与之同构）。

## 6. 硬件与成本映射

- 主实验走 API；嵌入与检索（bge/gte 类嵌入模型 + FAISS）全部本地跑，6GB 绰绰有余。
- 长程交互模拟的成本可观（模拟 100 段 50 轮对话 ≈ 数百万 token），先用 10% 规模冒烟并估算。
- 本地 1.5–3B 模型可作"低能力 agent"对照，研究记忆系统对弱模型的增益是否更大（性价比故事，审稿人喜欢）。
