# 领域包：多智能体协同（LLM Multi-Agent Collaboration）

## 0. 适配度与推荐切入角度（★★★★★）

纯 API 驱动，6GB 显存完全够用（本地只需跑小模型做对照或做评测辅助）。主要约束是 **API 成本**——多智能体实验的 token 消耗是单智能体的 5–20 倍，每个实验必须先估算成本。
推荐切入角度（按当前竞争格局）：**框架类工作（又一个 AutoGen）已是红海**；机会在**机制分析与失效研究**（为什么多智能体常常不如单智能体+好提示？错误如何在智能体间传播/放大？）、**通信与组织结构**（拓扑、角色分工、信息压缩对性能-成本前沿的影响）、**协同的评测科学**（现有 benchmark 能否区分"真协同"与"多次采样"）。

## 1. 领域地图

- 主线演化：角色扮演协作（CAMEL）→ 对话框架（AutoGen、MetaGPT 的 SOP 流水线）→ 辩论与自我纠错（Multi-Agent Debate）→ 组织结构与规模化（agent 社会、动态拓扑）→ 当前焦点：**什么时候多智能体真的有增益、增益来自哪**。
- 关键子问题：任务分解与分工；通信协议与信息瓶颈；错误传播与从众（一个 agent 的幻觉如何污染全组）；评审者/验证者角色的可靠性；成本-性能权衡；异构模型编组（强模型指挥弱模型）。

## 2. S1 定制

- 检索词族：`multi-agent LLM`、`LLM collaboration/debate`、`agent communication topology`、`multi-agent failure`、`orchestration`。
- 必读类型：CAMEL、AutoGen、MetaGPT、Multi-Agent Debate 原文；**近期的批判性论文**（质疑多智能体增益真实性的分析文章）是本领域最有信息量的读物；各 agent 框架 GitHub Issues 里的真实失败报告。
- 特别关注 OpenReview：该领域被拒稿件极多，拒稿理由高度模式化（见第 4 节），提前吸收。

## 3. 评测协议与基线

- 常用基准：GAIA（通用助理任务）、AgentBench、SWE-bench（软件工程）、GSM8K/MATH（推理，用于辩论类）、合作博弈/谈判类环境。注意：**不少 benchmark 对"协同"没有区分度**——单 agent 加反思提示就能打平，选基准时先做这个检验。
- 必备基线：单 agent（同等总 token 预算！）、单 agent + self-consistency（同预算多数投票）、单 agent + 自我反思。**同预算对照是本领域的生命线**：多智能体多花了 10 倍 token，不和"单 agent 花同样 token"比就是不公平对比，审稿人必杀。
- 指标：任务成功率 + **总 token 成本 + 延迟**，报告性能-成本曲线而非单点。

## 4. 领域特有陷阱（审稿雷区）

1. "增益其实来自多次采样"——没做同预算对照（最常见死因）。
2. 结果方差巨大：agent 系统随机性强，3 种子远远不够时要 5+ 种子，并报告失败案例的定性分布。
3. 框架工程贡献 ≠ 科学贡献：审稿人会问"你的发现换一个框架还成立吗"，至少在 2 个不同框架/模型上验证结论。
4. API 模型静默更新导致不可复现：锁定模型版本号，记录调用日期，关键实验留原始响应。

## 5. 创新点富矿（算子实例化）

- 假设反转："更多 agent/更多轮辩论更好"——实测常呈倒 U 曲线，何时、为何下降？"agent 间应共享完整上下文"——信息节食反而更好？
- 失效挖掘：收集协作失败案例，归类错误传播模式（从众、责任扩散、验证者橡皮图章化）。
- 机制追问：辩论提升成绩，到底是"观点碰撞"还是"变相多采样+格式化重述"？设计区分实验。
- 度量质疑：提出能区分"真协同增益"与"计算增益"的评测协议——这本身就是一篇 benchmark 论文。
- 跨域嫁接：组织行为学/分布式系统的原理（信息瓶颈、拜占庭容错、团队规模定律）在 agent 组织中是否同构成立？

## 6. 硬件与成本映射

- 全部主实验走 API；用 DeepSeek/Qwen 做主力（成本低、可固定版本），GPT 系列做泛化性验证。
- 典型成本量级：一次 500 题 × 3 agent × 3 轮的实验约数百万 token——先在 50 题子集上跑通并估算，全量前按宪法规则核算成本。
- 本地 GPU 的用途：跑 1.5B 小模型作为"弱 agent"研究异构编组；或本地部署嵌入模型做通信内容分析。
