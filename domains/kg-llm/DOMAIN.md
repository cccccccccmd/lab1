# 领域包：知识图谱 × 大模型（KG + LLM）

## 0. 适配度与推荐切入角度（★★★★☆）

图谱侧全是 CPU 活（图算法、SPARQL、子图抽取），LLM 侧走 API，本地 6GB 还能微调 ≤3B 的小模型做"图谱增强的小模型能否追平大模型"类研究——硬件匹配良好。
推荐切入角度：**KG 增强推理的机制分析**（图谱到底在什么问题类型上帮了忙、什么时候反而误导）、**LLM 辅助的图谱构建与质检**（构建方向竞争小于问答方向）、**图谱作为幻觉校验器**的可靠性边界。传统 KGQA 刷榜是红海且数据集老化，谨慎进入。

## 1. 领域地图

- 两条方向相反的主线：**KG→LLM**（图谱增强生成/推理：检索子图入 prompt、图上推理链如 Think-on-Graph / RoG 类）与 **LLM→KG**（大模型做信息抽取、图谱补全、schema 归纳、质量清洗）。
- 第三条新兴线：**GraphRAG 式混合**——从私域文本自动建图再检索，工业需求驱动，学术评测尚混乱（机会）。
- 关键子问题：子图检索的召回-噪声权衡；图结构信息的序列化方式（三元组文本化 vs 路径 vs 自然语言化）；多跳推理时图与参数知识冲突怎么办；图谱不完备时的鲁棒性；构建管线的错误累积。

## 2. S1 定制

- 检索词族：`knowledge graph LLM`、`KG-augmented reasoning/generation`、`graph retrieval augmented generation`、`LLM knowledge graph construction`、`knowledge conflict`。
- 必读类型：Think-on-Graph、RoG、GraphRAG 类代表作；知识冲突（parametric vs contextual knowledge）方向的分析论文——它是本领域机制问题的理论接口；KGQA 经典数据集论文（了解其构造缺陷，见陷阱 1）。
- 特别动作：把主流 KGQA 数据集（WebQSP、CWQ、MetaQA）各抽 30 题人工检查——数据老化与标注噪声的一手感受，是本领域选题的重要输入。

## 3. 评测协议与基线

- 常用基准：WebQSP、ComplexWebQuestions、MetaQA（多跳 KGQA）；事实核查/幻觉评测集（图谱作为校验器方向）；构建方向用信息抽取基准 + 人工评估子集。
- 必备基线：**无图谱的纯 LLM**（zero-shot + CoT，用最强 API 模型——很多老数据集上纯 GPT 级模型已接近饱和，先测这个再决定数据集是否还有区分度）、朴素 RAG（文本检索不走图）、检索子图直接塞 prompt（不做图上推理）。
- 指标：答案准确率 + **推理路径忠实度**（答对但路径错=没真用图谱）+ 图谱调用成本。

## 4. 领域特有陷阱

1. **数据集饱和与泄漏**：经典 KGQA 集年代久远，大模型可能背过答案——必做"遮蔽图谱后模型还能答对多少"的对照，剔除不需要图谱就能答的题再比较，否则全部结论虚高。
2. 图谱质量当作理所当然：实验用的干净学术图谱与现实的脏图谱差距巨大，至少做一组"图谱扰动/删边"鲁棒性实验。
3. 序列化方式是隐藏变量：三元组如何转文本对结果影响可达数个点，对比方法时必须统一或消融。
4. "图上推理"的忠实性：模型可能表面输出路径、实际靠参数知识作答——用反事实图（改掉图中事实看答案是否跟着变）检验。

## 5. 创新点富矿（算子实例化）

- 假设反转："图谱信息总是可信的、应覆盖模型参数知识"——冲突时谁对的概率更高？能否学一个仲裁器？
- 失效挖掘：图谱增强后**变差**的案例（图谱噪声误导、检索串台）系统归因——"图谱何时帮倒忙"是未被充分回答的好问题。
- 机制追问：图谱增强的收益随模型规模如何变化？（小模型收益大→性价比故事；大模型仍有收益→机制故事）
- 空白矩阵：静态图谱密集，时序/动态图谱 × LLM 稀疏；英文密集，多语言稀疏；问答密集，图谱**编辑与维护**稀疏。
- 组合失配：图神经网络与 LLM 的深度结合（不只是检索）为何一直没有干净的赢法？失败原因本身可研究。

## 6. 硬件与成本映射

- 图谱处理（NetworkX/igraph、子图抽取、SPARQL）全部本地 CPU；嵌入检索本地跑。
- LLM 推理走 API；KGQA 数据集规模适中（数千题），单轮全量评测成本可控（百万 token 级）。
- 本地微调用途：3B 模型 + QLoRA 训"图谱感知"的小模型，或训推理路径生成器——是本领域少数需要 GPU 的玩法，6GB 可行。
