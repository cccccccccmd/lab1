# 领域包：多模态大模型（Multimodal LLM）

## 0. 适配度与推荐切入角度（★★☆☆☆——需谨慎选角）

**坦率的警告**：这是七个领域里与你硬件最不匹配的一个。MLLM 预训练/全量指令微调完全不可行；即便 2B 级 VLM 的 LoRA 微调，6GB 也非常勉强（图像 token 多、激活大）。主流"造更强模型"路线的竞争者是有千卡集群的实验室——**不要正面进场**。
可行且有真实顶会先例的三条侧翼路线：
1. **评测与分析**（最推荐）：视觉幻觉、鲁棒性、偏见的系统性测量与归因，全走 API；
2. **数据研究**：指令数据的质量/配比/合成方法研究，用 API 造数据 + 极小模型或 API 微调服务验证；
3. **免训练方法**：解码策略、视觉提示（visual prompting）、多模型协作，纯推理侧创新。

## 1. 领域地图

- 主线演化：CLIP 对齐 → 视觉指令微调（LLaVA 范式：投影层+指令数据）→ 高分辨率/任意分辨率、视频与长视觉上下文 → 原生多模态与统一生成-理解模型 → 当前焦点：**视觉幻觉、细粒度感知（数数、OCR、空间关系）、多模态推理**。
- 关键子问题：视觉信息进语言模型的瓶颈（投影/token 化损失了什么）；语言先验压倒视觉证据（幻觉主因）；评测污染与选项偏置；视觉思维链的忠实性。

## 2. S1 定制

- 检索词族：`multimodal LLM / VLM`、`visual hallucination`、`visual instruction tuning`、`MLLM evaluation/benchmark`、`training-free VLM`。
- 必读类型：LLaVA、Qwen-VL、InternVL 技术报告（了解主流配方即可，不必深钻训练细节）；幻觉评测（POPE、HallusionBench 类）与 MMMU/MathVista/MMBench 的论文，**重点读其错误分析与已知缺陷讨论**；质疑 benchmark 有效性的分析论文（选项偏置、语言捷径）——本领域此类论文常中顶会，是你的对标物。
- 特别动作：抽 50 道主流 benchmark 题目人工做一遍，感受"不看图能答对多少"（语言捷径的严重度）。

## 3. 评测协议与基线

- 常用基准：MMMU（学科推理）、MathVista（数学视觉）、MMBench、POPE/HallusionBench（幻觉）、OCR/文档理解类。
- 分析类工作的"基线"是**被测模型池**：覆盖 2–3 家 API 大模型 + 2–3 个开源小 VLM（API 或云端推理），结论须跨模型成立。
- 免训练方法的基线：原始解码 vs 你的解码/提示策略，同模型同预算对比。
- 指标纪律：多选题必须报告**选项顺序扰动后的稳定性**；幻觉评测报告"是/否"回答偏置校正后的数字。

## 4. 领域特有陷阱

1. 语言捷径：模型不看图也能答对的题目占比可观——所有结论先在"图片遮蔽对照"上校准，这是本领域分析工作的第一道工序。
2. Benchmark 污染快：新基准发布数月后即可能进入训练数据，测 API 模型时注意基准发布时间。
3. 开源 VLM 的推理配置（分辨率、图像 token 数、system prompt）对结果影响巨大且论文常不写全——复现时逐项核对，报告时逐项公开。
4. "视觉推理"与"视觉感知"混淆归因：错误到底出在看错（感知）还是想错（推理）？归因时用"给出完美图片描述再答题"的 oracle 对照拆分。

## 5. 创新点富矿（算子实例化）

- 失效挖掘：某类细粒度任务（计数、空间关系、否定）的系统性失败归因——感知瓶颈还是语言先验压制？
- 度量质疑：现有幻觉指标能否被"更保守地回答"策略刷高而幻觉本质未减？设计抗策略的评测。
- 机制追问：视觉思维链是真"看着想"还是先答后编？用注意力/扰动实验检验忠实性。
- 极限降解：把图像 token 压到 1/10，哪些能力先崩？——视觉信息瓶颈的量化研究，小算力可做。
- 组合失配：为什么检索增强在多模态问答上的收益远不如纯文本？障碍本身可研究。

## 6. 硬件与成本映射

- 评测/分析路线：全 API，单次全基准评测数十万到数百万 token，成本可控。
- 数据路线：API 造数据本地存；验证微调若必需，用云 GPU 短租（在日志中走预算审批），或改用 API 微调服务。
- 本地 GPU 用途有限：跑 CLIP/SigLIP 类小模型做图文相似度分析、跑 2B VLM 的纯推理（4bit）做对照点。
